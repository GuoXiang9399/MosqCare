一、概览

背景与问题

蚊虫饲养是媒介实验室内持续性、日常性的基础工作：一批蚊虫从卵到成虫要经历多个生命阶段，期间伴随每日的温湿度巡视、饲喂、计数分笼与实验处理。目前这些过程大多依赖纸质记录本和分散的表格，带来三类典型问题：

  • 记录分散、回溯困难。同一蚊笼的卵量、孵化、分笼、饲喂、环境数据散落在不同位置，回溯一次完整生命周期要翻查多个来源。
  • 指标滞后、异常发现晚。存活率、化蛹率等指标靠事后手工计算；温度超标、存活率偏低往往在影响发生后才被发现。
  • 产能不清、谱系难追。每个品系能稳定产出多少成虫、哪一世代表现更好，缺乏现成的统计视图。

用户与核心任务

要素定义
主要用户实验室饲养人员（1–2 人，共用同一台电脑，单机使用，无账号体系）
核心任务把每个饲养蚊笼从卵到成虫的全过程记录在册，并随时回答三个问题：这批养得怎么样？出了什么问题？本室能产出多少？
旅程触发收到新一批卵（亲代产卵收集或野外采集）需要建立饲养蚊笼；或每日巡检时需要补记环境 / 饲喂 / 计数
完成标志蚊笼结束归档后，在统计分析页可查到该蚊笼的产能与存活率；全生命周期记录可追溯
共享对象饲养蚊笼（Cage）：隶属于品系，承载全部记录、指标与预警，是统计主线

F8质量预警阈值在预警中心面板内配置；环境超标 / 存活率偏低 / 饲喂超时 / 记录断档自动检测，预警附处理建议
F9单页饲养报告以 AeLabStr v1.4 记录单为模板，每笼可导出 / 打印单页饲养报告（含记录台账）
F10设置数据与备份提醒开关；CSV 导出内置于各面板，不设独立导出入口；预警阈值配置见预警中心（F8）
F11关于独立面板（侧栏入口）：软件介绍、版本更新日志与联系方式
F12IoT 接入温湿度传感器自动采集、摄像头实时画面与快照、插座开关远程控制；内置米家连接器（小米账号登录直连，无需自建 Home Assistant），各区域附接入指南

P1 与非目标

P1（下一迭代候选）：蚊笼标签打印、发育历期基准、血饲供体字段扩展、Windows 桌面安装包。CSV 导入 / 导出已内置于品系档案与蚊笼列表（导出另覆盖统计分析 / 预警中心），不设独立「数据导出」入口。

非目标（明确不做）：多用户账号与权限体系、云同步、试剂耗材库存管理。温湿度仪器自动采集已随 F12「IoT 接入」从非目标转为正式功能（内置米家连接器直连）；环境记录保留来源字段区分手动 / 自动。

假设与待定

  • 假设默认预警阈值取常用饲养参数（温度 24–28℃、湿度 65–85%、累积存活率 80%、幼虫期饲喂间隔 24h、记录断档 48h），需按本室规程确认；系统内可调整。
  • 假设发育历期基准（用于「偏快 / 偏慢」评价）暂不定义，v1 仅展示实际值。
  • 假设数据存储于本机，备份由使用者执行；备份提醒开关见「设置」（F10）。
  • 待定血饲供体类型（活体麻醉小鼠 / 人工膜）及动物伦理合规的记录要求，确认后在「实验处理」记录中补充对应字段。

二、设计

核心旅程（P0）

  1. 建笼 — 收到卵后新建蚊笼：选品系、世代号、起始卵量；系统自动生成「卵入笼」首条记录，蚊笼进入「饲养中 · 卵期」。
  2. 日常记录 — 每日巡视补记环境与饲喂；阶段转换时全数 / 抽样计数并记录淘汰数。环境超标或存活率跌破阈值时即时生成预警。
  3. 过程查看 — 蚊笼详情页实时呈现阶段进度、累积存活率、阶段历期与完整时间线。
  4. 异常预警 — 预警中心列出待处理预警并给出处理建议。
  5. 结束归档 — 终末计数复核后结束蚊笼（不可逆，二次确认），进入产能统计。
  6. 复盘分析 — 统计页按品系 / 时间范围查看存活率、历期、环境关联与产能。

恢复路径：记录录错 → 新增一条说明性备注记录（F5）；环境超标 → 按预警建议处理（F8）；误结束蚊笼 → 不重开，另建新笼并在备注中关联说明。

对象模型

系统围绕三个对象组织：品系（Strain）是长期档案，记录种名、编号、来源，是蚊笼的归属；蚊笼（Cage）是统计与预警的主线对象，一次「卵入笼到结束」为一个蚊笼，同世代分笼扩繁即为多个蚊笼；记录（Record）是蚊笼下的流水，分阶段计数、饲喂、环境、实验处理四类，只增不改。

对象关键字段关系
品系 Strain编号、种名、拉丁名、来源1 → N 蚊笼
蚊笼 Cage笼号、世代、起始日期、起始卵量、当前阶段、当前数量、状态1 → N 记录；1 → N 预警
记录 Record类型、日期时间、数量 / 参数、备注归属唯一蚊笼

蚊笼状态机

状态定义与流转规则的唯一权威定义见「规则与口径」页。设计要点：「饲养中」是唯一可记录状态；「已结束 / 已废弃」为终态，进入后蚊笼只读、不可新增记录、待处理预警自动关闭；误操作不通过重开恢复，而是另建蚊笼并备注关联。

关键产品决策

#决策理由
1以「蚊笼」而非「个体」为主线蚊虫饲养以群体为单位管理，个体级追踪成本不可接受 [产品判断]
2阶段严格顺序推进，转入阶段只能为当前阶段的下一阶段符合生物学过程，杜绝跳段录入错误 [产品判断]
3记录不可删除、不可改数，只增不改饲养数据是实验追溯依据，保留完整痕迹比整洁更重要 [产品判断]
4单机、无登录1–2 人共用一台电脑，账号体系收益低于成本；数据安全靠本机管控与备份 [产品判断]
5预警阈值可配置，默认值取常用参数不同品系与本室规程差异大，硬编码会立即失效 [产品判断]

数据说明

原型中的品系、蚊笼、记录与统计图表均为示例数据，仅用于展示计算口径与交互行为，不代表真实实验结果。

三、功能需求

以下每个小节与左侧原型中的对应区域通过 F 编号互链。计算口径、状态机的唯一权威定义见「规则与口径」页，此处仅引用不重复。

F1

工作台总览

目的：打开即回答「今天该做什么、总体养得怎么样、有没有异常」。工作台不设独立概览区，直接以蚊笼为单位组织首页：虫态以图形化图标呈现，预警直接标注在对应蚊笼卡片上。

行为与规则

  • 关键指标卡：在养蚊笼数、在养虫数（在养蚊笼当前数量之和）、待处理预警数。指标卡点击跳转对应页面。
  • 蚊笼卡片：每只在养蚊笼一张卡片，以二次元萌系风格虫态图标（卵 / 幼虫 / 蛹 / 成蚊：水润大眼、腮红、微笑与星光点缀，蛹附 Zzz 瞌睡细节）与颜色区分当前阶段；实际饲养中同一蚊笼常存在多阶段并行（如蛹期与成虫期并存），主图标显示主体阶段，并存阶段以右下角小徽章与「+ 阶段名」文字标注；展示笼号、蚊株名称（不显示世代）、当前阶段与数量；不显示累积存活率与饲喂记录（详情见蚊笼详情页）。卡片网格一行 4 张且各卡片等宽、等高。
  • 预警上卡：该蚊笼的待处理预警以标签形式直接展示在卡片上（最多 2 条 + 数量汇总），点击标签进入预警中心；预警消除后标签即时消失。预警区为固定占位（无预警时留白），保证所有卡片等高对齐。
  • 卡片操作：「详情」进入蚊笼详情（F3），「记录」打开记录表单（F4）。
  • 首页布局：不设「新建蚊笼」按钮与需求链接入口；指标卡行与蚊笼卡片网格之间以分隔线区分；卡片网格默认一行 4 张（窄屏降为 2 张）。

状态与边界

  • 暂无在养蚊笼时显示引导文案「暂无在养蚊笼，请前往「蚊笼管理」新建」。
F2

品系档案与蚊笼管理

目的：建立「品系 → 蚊笼」两级台账，建笼即建账。品系档案为左侧栏独立栏目；「蚊笼管理」页仅保留蚊笼列表。

品系档案

卡片展示编号、种名 / 拉丁名、来源、在养蚊笼数与历史世代数。点击品系卡片可打开代系详情：代系关系以树状呈现（按亲代蚊笼逐层展开，一个蚊笼可扩繁出多个子代蚊笼，节点显示笼号 / 世代 / 阶段 / 数量 / 存活率，在养节点高亮，点击节点进入蚊笼详情）与关联蚊笼（该蚊株全部蚊笼列表）。物种与蚊株信息可编辑：弹窗内「编辑信息」可修改名称、蚊株、蚊株缩写、物种（拉丁名）、来源与备注，保存后即时生效。蚊株缩写用作该株新建蚊笼的笼号前缀（如佛山株缩写 FS，新笼自动编为 FS-01、FS-02…；缩写为空时以 C 前缀），品系卡片与弹窗均展示缩写标签；品系 CSV 增加末列「蚊株缩写」（可空，旧文件缺该列时可正常导入）。

数据导入 / 导出：面板标题区提供「＋ 新增品系 / 导入 CSV / 导出 CSV」。导出生成真实 CSV 文件（蚊株、名称、物种编码、拉丁名、来源、备注、蚊株缩写七列，末列可空）；导入按相同列序合并，蚊株已存在则更新、否则新增，完成后提示新增 / 更新 / 跳过条数。假设。

蚊笼列表

  • 列：笼号、品系 / 世代、起始日期、当前阶段、当前数量、累积存活率、状态、操作。
  • 筛选：状态（全部 / 饲养中 / 已结束 / 已废弃）与品系；无结果时显示空态卡片。
  • 行操作：「详情」进入蚊笼详情；「记录」打开记录表单（F4）；「报告」导出单页饲养报告（F9）。
  • 数据导入 / 导出：标题区「导出 CSV」生成真实文件（笼号、蚊株、世代、亲代笼、起始日期、起始卵量、当前阶段、数量八列，含已结束蚊笼）；「导入 CSV」按相同列序合并，笼号已存在则更新基础字段、否则新建蚊笼（蚊株须已存在于品系档案，阶段须为合法虫态，否则该行跳过并计入提示）。

新建蚊笼

  • 必填：品系（下拉随品系档案实时更新）、世代号（格式 F + 数字）、起始日期（默认今天，不得晚于今天）、起始卵量（≥ 1 的整数）；选填：亲代蚊笼（从在养蚊笼中选择，选定后世代号自动填为亲代世代 +1、来源说明自动填为「亲代蚊笼 ×× 产卵收集」）与来源说明。
  • 笼号自动生成（C-流水号），不可编辑。
  • 提交后自动生成「卵入笼」记录，蚊笼置为「饲养中 · 卵期」，并进入蚊笼详情。
  • 同一品系下世代号可重复（同代分笼扩繁），重复时提示确认后允许，避免误填 [产品判断]。
F3

蚊笼详情与生命周期时间线

目的：单一蚊笼的全貌视图：现在到哪一步、指标如何、发生过什么。

生命周期进度条

按 卵 → L1 → L2 → L3 → L4 → 蛹 → 成虫 横向呈现；已发生阶段显示当时转入数量与转入日期（MM-DD），当前阶段高亮，后续阶段置灰显示「未记录」。格子均分整行宽度、不出现横向滚动条，完整周期一屏可见。

指标区

核心指标直接呈现在生命周期进度卡片中，不单独分组：首张卡片标注起始卵量；每张卡片显示该阶段数量与转入日期；阶段间标注阶段存活率（本阶段数量 ÷ 上一阶段数量）；当前阶段标注「进行中」并附累积存活率（当前数量 ÷ 起始卵量，口径见「规则与口径」）。孵化率 / 化蛹率 / 羽化率在「统计分析（F7）」中按蚊笼汇总呈现。

记录时间线

  • 全部记录按时间倒序，类型以色块图标区分；数量变化以 +/− 徽标展示，含淘汰数。
  • 详情头部为操作入口：「＋ 新增记录」主按钮（弹出记录表单，F4，仅饲养中可用）、「结束蚊笼」（F6，仅饲养中可用），以及「编辑 / 删除」蚊笼入口。

状态与边界

  • 已结束 / 已废弃蚊笼进入只读视图：顶部显示终态横幅（结束原因、日期），不可新增记录。
F4

日常记录录入

目的：把四类日常动作沉淀为结构化记录，录完即算、异常即警。

入口与表单

入口：蚊笼详情操作按钮、蚊笼列表行内「记录」。四种类型共用一个模态，页签切换：

类型字段（* 必填）关键校验
阶段计数日期*、转入阶段*、计数方式、转入数量*、淘汰数、备注日期在蚊笼起始日与今天之间；转入阶段必须为当前阶段的下一阶段；转入数量 ≥ 1；转入 + 淘汰 ≤ 当前数量
饲喂日期时间*、类型*（糖水 / 幼虫饲料 / 血饲）、规格*、方式、备注日期时间不晚于当前时刻
环境日期时间*、温度*、相对湿度*、光周期、备注温度 10–40℃、湿度 20–100%；超出预警阈值时保存后立即触发预警
实验处理类型*（取样送检 / 分装扩繁 / 药物处理 / 感染饲毒 / 添加产卵杯 / 其他）、移出当期个体数、去向 / 用途、操作人、备注移出数量 ≥ 0 且 ≤ 当前数量；分装扩繁时提示「另建同世代子笼并备注关联」

提交行为

  • 校验通过 → 保存并置顶于时间线 → 蚊笼阶段 / 数量 / 指标即时更新 → 提示「记录已保存」。
  • 满足触发条件时自动生成预警（环境超标、累积存活率低于阈值），同笼同类型待处理预警去重，不重复堆叠（检测规则见 F8）。
  • 校验失败 → 字段级错误提示，已填内容保留。
F5

记录台账

目的：完整保留饲养过程信息，形成可追溯的记录台账。

规则

  • 记录只增不改：阶段计数、环境、饲喂、实验处理、结束等记录一经保存即不可删除或修改。
  • 填写错误通过新增一条说明性备注记录说明，不影响既有数据。
  • 记录时间线按时间倒序展示，支持生成饲养记录单导出。
F6

蚊笼结束与产出确认

目的：把「养完了」变成一条可信的产出记录，进入产能统计。

流程

  1. 入口：蚊笼详情「结束蚊笼」，仅「饲养中」状态可用。
  2. 表单：结束日期（默认今天）、终末阶段、终末数量（≥ 0）、结束原因（产卵收获 / 实验取用 / 自然淘汰 / 全量废弃）、备注，并必须勾选「我已复核终末数量与阶段」。
  3. 提交后弹出不可逆确认条（红色），二次确认后生效。
  4. 结果：状态置为「已结束」（原因为「全量废弃」时置「已废弃」）；生成终末记录；该蚊笼待处理预警自动关闭（标记「蚊笼结束」）；详情转只读；蚊笼进入产能统计（F7）。

恢复

  • 结束不可撤销。误结束时另建新蚊笼，并在备注中写明关联笼号。
F7

统计分析

目的：回答「养得怎么样、和什么有关、能产多少」。

筛选

品系（全部 / 单选）与时间范围（近 30 / 90 天、全部，按蚊笼起始日期）。

图表与规则

  • 图表卡片按两列排布：第一排 平均发育历期、阶段转化率；第二排 各蚊笼累积存活率、世代对比；第三排 月度产出趋势、各蚊株累积产出。
  • 平均发育历期（卵 / 幼虫期 / 蛹期，按品系分组对比）；阶段转化率（已结束蚊笼平均孵化率 / 化蛹率 / 羽化率，附计算口径；仅纳入阶段记录齐备的蚊笼）。
  • 各蚊笼累积存活率（横向条形，按存活率降序，仅纳入已结束蚊笼）。
  • 各蚊株累积产出（按蚊株聚合已结束蚊笼的终末成虫合计）。
  • 按钮卡片入口：面板底部提供「产能报表」与「环境与存活关联」两个按钮卡片，点击在弹窗中查看——产能报表为已结束蚊笼明细表；环境与存活关联为蚊笼平均饲养温度 × 累积存活率散点图（样本 ≥ 3 时呈现，页面明示「仅呈现相关性，不构成因果结论」）。
  • 世代对比：按品系 / 世代聚合全部蚊笼（含在养，标注「含在养」）展示累积存活率；含在养蚊笼的即时存活率仅供监测参考，正式对比以已结束蚊笼为准。
  • 面板标题区提供「导出 CSV」，将当前图表数据导出为 CSV 文件（当前版本以示例数据生成提示）。
  • 筛选后样本量不足 3 时，图表区显示「样本不足，暂不呈现，避免误读」；产能报表正常展示。

各指标计算口径见「规则与口径」。

F8

质量预警

目的：把异常从「事后发现」变为「发生即知」，并给出处理建议。

检测规则

类型触发条件触发时机级别
环境超标温度 / 湿度超出阈值环境记录保存时警告
存活率偏低累积存活率低于阈值阶段计数保存时警告
饲喂超时卵期至 L4 期蚊笼距上次饲喂超过阈值打开工作台时提示
记录断档在养蚊笼距上次任意记录超过阈值打开工作台时提示

默认阈值见「规则与口径」；预警中心面板顶部提供阈值配置区，可直接修改温度 / 湿度上下限、存活率下限、饲喂间隔与记录断档上限并保存。

F12

IoT 接入

目的：将蚊房环境与设备的采集、观察、控制纳入工作台闭环，减少手工记录、支持远程查看与自动化联动。定位在「蚊笼管理」与「统计分析」之间。

接入路径（详见调研报告）：软件内置米家连接器，减少用户折腾。实现方式不是自研云接口（米家云 API 不对个人开放），而是内嵌小米官方开源的米家集成内核（与官方 Home Assistant 集成同源，支持个人小米账号登录）：用户在软件内登录米家账号即可自动发现与控制设备，体验上等于「账号直连」，无需安装 Home Assistant。温湿度传感器走蓝牙直连（断云可用）；智能插座经局域网协议控制；摄像头建议选用固件带 RTSP 开关的型号（走局域网低延迟通道）。Home Assistant 完整版为可选高级路径。待定官方内核的开源许可用于商业打包的合规性需在正式化阶段确认。

三个开发方向

  • 温湿度传感器：设备卡片展示实时温湿度、型号、连接方式与绑定蚊笼；按 15–60 分钟间隔自动采集，写入对应蚊笼的环境记录（来源标「自动采集」），并复用 F8 阈值触发预警；支持「立即采集」手动触发。
  • 摄像头：设备卡片展示取流就绪状态与关联蚊笼；详情弹窗经内置连接器播放实时画面（固件开启 RTSP 时走局域网通道），支持快照存证并关联蚊笼记录；无 RTSP 开关的型号不支持取流，选购需注意。
  • 插座开关控制：恒温加热垫、循环风扇、光周期定时等设备的远程开/关；展示用途与关联蚊笼；可与预警联动（如温度持续超下限自动开启加热垫，需人工确认后启用）。

当前版本范围：面板结构与交互已就绪（由内置示例数据驱动：米家账号登录态、同步设备、立即采集写记录、查看画面弹窗、开关切换）；真实设备链路经内置米家连接器，在后续版本接入。

四、规则与口径

蚊笼状态机（唯一权威定义）

状态进入条件允许操作出口
饲养中新建蚊笼（卵入笼）全部记录类型、结束蚊笼已结束 / 已废弃

已废弃结束蚊笼（原因：全量废弃）只读查看终态，不可逆

生命周期推进与计数口径

  • 阶段序列固定：卵 → L1 → L2 → L3 → L4 → 蛹 → 成虫；转入阶段必须为当前阶段的下一阶段，不允许跳段。
  • 每次阶段推进以一条阶段计数记录为准；「当前数量 = 最近一次阶段计数的转入数 − 其后实验处理移出量」。
  • 「转入 + 淘汰 ≤ 当前数量」约束防止数量凭空增加。
